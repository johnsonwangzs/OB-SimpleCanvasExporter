# 导出 HTML 的纯色背景方案

日期：2026-09-17。版本：0.5.0。状态：已实现；本文保留设计依据与交互规则。

用户已确定：尽量在当前浏览器记住每份 HTML 的选择。

## 1. 推荐方案

在导出页第一行工具栏的“适应全图”右侧增加 **背景** 按钮，前面显示当前颜色的小色块。点击打开紧凑的非模态浮层，提供常用纯色、原生颜色选择器、HEX 输入以及“恢复导出原色”。有效颜色即时作用于画布，无需“应用”按钮；关闭浮层保留当前效果。

本方案将“背景”定义为画布空白区域。卡片正文、工具栏、搜索区、Badge、阅读面板、连接线和文字维持导出时的配色。含透明或半透明背景的卡片会自然透出新的底色；不承诺它们的最终合成外观完全不变。

这是导出后阅读页的功能。无需新增 Obsidian 设置项，也不影响原始 Canvas。旧 HTML 需要重新导出。0.5.0 先支持不透明纯色；渐变、图片背景、透明度、整套明暗主题切换、另存配色副本暂不纳入。

## 2. 入口和浮层

```text
Canvas 标题    卡片 / 连接数       [−] [+] [100%] [适应全图] [■ 背景]
                                                           ↓
                                            画布背景           [×]
                                            常用颜色
                                            [纯白] [浅灰] [米白]
                                            [墨黑] [深灰] [蓝灰]
                                            自定义颜色
                                            [色块] [#F5F1E8     ]
                                            [恢复导出原色]
                                            已在此浏览器记住
```

- 常态只增加一个按钮，不增加常驻工具栏行。窄屏允许现有控件自然换行，保留“背景”文字。
- 桌面浮层约 288px 宽，贴近按钮并限制在视口内；窄屏保持左右至少 8px 边距。浮层可在高度不足时滚动，不改变画布可用尺寸。
- 面板使用原导出主题的不透明背景，换色时始终可读。与 Badge 完整目录互斥；打开背景关闭 Badge 浮层，反向同理。阅读面板可同时存在。
- 当前预设用勾选及 `aria-pressed` 表示，不只用颜色表示。色块应有边界，白色也能辨认；按钮有颜色名称与 HEX 的可访问标签。
- 色板按固定顺序显示，避免深浅主题间改变位置。它们是快捷选项，不宣称在所有主题下都有最优对比度。

| 名称 | HEX |
| --- | --- |
| 纯白 | `#FFFFFF` |
| 浅灰 | `#F5F5F5` |
| 米白 | `#F5F1E8` |
| 墨黑 | `#1E1E1E` |
| 深灰 | `#282828` |
| 蓝灰 | `#202631` |

## 3. 换色和恢复

| 操作 | 行为 |
| --- | --- |
| 点击预设 | 立即改变背景，同步 HEX 和颜色选择器，尝试记住 |
| 拖动原生选色器 | `input` 即时预览，`change` 提交并尝试记住；不在每次拖动事件中写存储 |
| 输入 HEX | 接受带或不带 `#` 的三位、六位 HEX，去除两端空格；Enter 或失焦时提交，统一显示六位大写 |
| 输入未完成或非法值 | 保留最后有效背景，不写存储；提交时在输入框下提示“请输入 3 或 6 位 HEX 颜色”，标记 `aria-invalid` |
| 点击另一预设 / 恢复 | 丢弃未提交的输入草稿，清除错误，以新操作为准 |
| 关闭浮层 | 保留已经生效的背景；丢弃无效输入草稿，重新打开显示当前有效值 |
| 恢复导出原色 | 删除自定义覆盖和此文件的已存偏好，精确恢复导出时的背景；不重置搜索、Badge 或视图 |

初始使用导出原色；存在合法的已存偏好时才覆盖。默认态与自定义态分别表示，即使自定义 HEX 恰好等于原色，也不能据此认定偏好已经清除。

原色可能是 `rgb()` 或其他浏览器计算色值。恢复应移除覆盖、回到原始 CSS，不能用经过 HEX 舍入的值替代。原生颜色选择器需要六位 HEX 时，只对控件值做转换；这不改变默认背景。转换不支持时保留“导出原色”状态，仍可选预设或输入自定义 HEX。

选色器弹窗由浏览器管理，取消和 Escape 先遵循原生控件行为，不承诺各浏览器提供相同的取消预览机制。页面关闭浮层时不得留下未同步的控件状态。

## 4. 记住选择

用户期望是阅读偏好在同一浏览器、同一导出文件地址下尽量延续。

- 每次导出生成独立的 `exportId` 写入 HTML。存储键使用版本命名空间、`exportId` 和当前文档地址（去掉 query / hash），不使用标题作为唯一标识；同名导出、同站点不同文件互不覆盖。
- 仅保存归一化的六位 HEX。读取时再次校验，损坏或未知格式忽略，使用原色。新导出使用新 ID，不自动继承上一份文件的选择。
- 复制或移动到新地址、更换浏览器、无痕窗口、清理浏览器数据后，不保证保留。偏好不写入 HTML，发送文件给别人时仍从导出原色开始。
- `localStorage` 的获取、读取、写入、删除均使用异常保护；失败不能阻止缩放、搜索、筛选或阅读初始化。
- 成功写入后才显示“已在此浏览器记住”；写入失败显示“仅本次打开有效”。恢复时删除失败应说明“已恢复原色，但未能清除记忆；再次打开可能使用旧颜色”。
- 不弹系统告警，不要求登录、联网或请求文件写入权限。提示放在浮层底部，关闭后不占画布空间。

直接以 `file:` 打开的 HTML，其 `localStorage` 行为没有统一保证，因此“记住”是尽力支持，不能作为换色功能的前提。[MDN：Window.localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

早期内联示意只演示选色、校验和恢复；正式导出的 HTML 已接入上述浏览器存储逻辑。

## 5. 与现有功能配合

- 换色和开关浮层不触发 `fit()`、搜索重建或正文重新渲染，保持缩放、画布中心、当前结果、卡片滚动、阅读面板滚动及字号。
- 背景浮层内部操作不会触发画布拖动。点击画布外部区域关闭浮层后，应避免同一次点击产生意外平移；正常后续拖动保持可用。
- 不根据新背景自动改连接线、卡片、搜索描边或 Badge 颜色。某些颜色组合会降低连线可见度，用户可立即恢复原色；不在此版本引入自动重着色或对比度评分。
- 连接标签、当前结果标签、阅读入口及底部操作提示继续使用原主题的前景 / 背景配对；空画布提示也使用有可读底色的提示区域。
- 关闭阅读面板后应看到用户所选背景；窄屏阅读面板覆盖画布时，换色仍有效，但不会强行关闭阅读内容来展示效果。
- 打印沿用导出原色，隐藏背景按钮及浮层；用打印 CSS 覆盖展示，不改内存选择或存储。浏览器是否打印背景仍由打印设置决定。
- 脚本禁用时隐藏背景入口，保留原来的静态阅读回退。

## 6. 键盘和触屏

- 入口使用原生按钮，带 `aria-expanded`、`aria-controls`；浮层使用有标题的非模态 `dialog` 语义。
- 键盘打开时聚焦已选预设；没有已选预设时聚焦自定义颜色控件。使用自然 Tab 顺序，不锁定焦点。
- Escape 只关闭当前浮层并把焦点还给入口，不清搜索或关闭阅读面板；遵守原生选色器和输入法的优先处理。
- 点击关闭按钮后焦点回入口；点击外部或 Tab 离开时保留用户目标焦点，不抢回入口。
- 控件提供明确标签；错误关联到 HEX 输入框，提交结果使用简短的 `aria-live` 提示，不播报每帧预览。
- 触屏点击目标至少约 44×44px；编辑字段使用适合触屏的字号；320px 宽屏不横向溢出。

## 7. 基于当前代码的落点

已检查 0.4.0 源码：`src/export.ts` 的 `theme()` 输出 `--sce-bg`，`src/styles.ts` 让画布、工具栏、阅读面板和多个标签共用该变量。因此必须隔离画布背景，不能直接在 body 上改 `--sce-bg`。

| 文件 | 实现职责 |
| --- | --- |
| `src/viewer-html.ts` | 背景入口、浮层和状态提示；默认隐藏入口，由运行时启用 |
| `src/styles.ts` | `.sce-viewport` 使用 `background: var(--sce-canvas-bg, var(--sce-bg))`；浮层、窄屏、触屏、打印规则；原有界面继续使用 `--sce-bg` |
| `src/viewer.ts` | 自包含的颜色归一化、应用、恢复、记忆及浮层状态；协调 Badge / reader 的 Escape 和焦点处理 |
| `src/export.ts` | 为本次输出生成独立 UUID 作为 `exportId`；背景由文末的自包含阅读脚本同步恢复 |
| `src/i18n.ts` | 新增中英文文案 |
| `scripts/background-browser-test.mjs` | 独立浏览器验收，并复用真实冻结内容；实际导出组装器生成空画布验证 UUID 和序列化运行时 |

运行时仍由 `startViewer.toString()` 内嵌，新增逻辑不得依赖未序列化的模块变量。启动阶段仅对合法 HEX 调用 `style.setProperty`；不把输入字符串拼成样式表。恢复原色使用 `removeProperty`。外观更新不遍历或重写冻结的正文树。

当前没有额外首屏恢复脚本，保持一份存储键及校验逻辑。浏览器运行时在启用交互和适应全图前同步恢复颜色；失败立即使用原色。

## 8. 实现验收

1. 默认原色、六个预设、原生自定义颜色、三位 / 六位 HEX、非法输入、精确恢复都符合交互规则。
2. 同一文件刷新后恢复偏好；不同导出 ID / 地址相互隔离；禁止存储、写满、损坏记录、删除失败均正常降级。
3. 换色前后画布坐标与缩放、搜索及 Badge 结果、卡片和阅读面板滚动不变；只有背景变量改变。
4. 深浅导出主题和 Prism 真实冻结样例可读；普通 / 彩色 / 半透明卡片、连线标签、空画布都覆盖。
5. 验证背景与 Badge 浮层互斥、Escape 优先级、Tab 离开、焦点返回、触屏选色、不误拖画布。
6. 在 320、650、1360px 下验证长标题和已有工具栏换行；打印隐藏新控件并使用原色；禁用脚本静态阅读正常。
7. 离线打开不发起网络请求；通过现有 `pnpm check` 及搜索、阅读、Badge 回归，再更新版本文件、README 与 CHANGELOG。

实际执行的测试、环境及边界见 [TESTING.md](TESTING.md) 的 0.5.0 记录。原生系统选色器的外部窗口仍由浏览器提供；自动化验证其 input / change 事件，不声称已手动覆盖所有系统选色器。
