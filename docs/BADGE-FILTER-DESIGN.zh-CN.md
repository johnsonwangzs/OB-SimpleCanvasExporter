# 导出 HTML 的 Badge 筛选方案

日期：2026-09-17。状态：已在 v0.4.0 实现；本文保留设计依据与交互规则。

## 1. 推荐方案

在现有搜索框下方增加一排 **Badge 筛选项**。从本次导出的文本卡片中收集实际出现的 Badge，去重后显示文字、原配色及覆盖的卡片数；点击切换选择。

关键词负责查找正文，Badge 负责按标记筛选卡片。两者可以独立使用，也可以叠加；结果继续使用已有的卡片描边、非结果淡化、连线淡化、结果导航和阅读面板。

仅增强导出的 HTML，不修改原始 Canvas，不读取或编辑 SimpleBadge 预设，不在浏览器中运行 Obsidian 插件。

## 2. 已核实的基础

- OB-SimpleBadge 0.6.0 的 `src/model.ts` / `src/badge.ts` 输出两种稳定格式：`span.badge.badge-{主题色}`，以及带有 `--simple-badge-color` HEX 值的 `span.badge.badge-custom`。
- SimpleBadge 以**文字和颜色的组合**判断相同 Badge；文字区分大小写、去除首尾空白，HEX 统一为小写六位。相同文字但不同颜色可分别存在。插入正文的 span 不带预设 ID；之后修改预设也不会追溯改写已有 span。
- 当前导出器已保留 Badge 的 class、正文和冻结后的外观；但 `freezeTree` 不保留原始自定义 CSS 变量。因此自定义颜色的语义需要在导出时补充，不应只按 `badge-custom` 合并。
- 当前实际样例 `example-canvas (5).html` 中有 16 个 Badge span，分为 5 种：

| Badge | 颜色类型 | 覆盖卡片 |
| --- | --- | ---: |
| post-hoc | purple | 5 |
| logits-based | green | 5 |
| sampling-based | cyan | 3 |
| sentence-level | pink | 2 |
| distortion-free | blue | 1 |

这些数字来自原始画布文本卡片，未计入阅读面板副本。

## 3. 搜索区布局

保留搜索框及导航按钮，在其下方添加独立一行：

```text
[搜索文本卡片…                 ] [清除]  [上一张] [下一张] [查看全部结果]
Badge  [post-hoc 5] [✓ logits-based 5] [sampling-based 3] … [重置 Badge]
符合条件 5 张                             [✓ 淡化其他卡片]
```

- Badge 保留文字、文字颜色和浅色背景；工具栏统一使用可读字号和点击区域，不照搬正文中的字号比例。
- 选中项增加勾选符号和外框，不用统一强调色覆盖 Badge 原配色。再次点击取消选择；支持 Tab 与 Space / Enter，使用按钮及 `aria-pressed`。
- Badge 后面的数字表示“当前文档内包含该 Badge 的卡片数”，同一卡片重复出现只计一次。该数字固定，不随搜索或选择跳动；筛选后的数量显示在结果状态中。
- 固定按覆盖卡片数降序排列，同数按首次出现位置排序。选择和搜索不重新排序。
- 当前样例只有 5 种，可以全部常驻。数量多时主栏最多两行，剩余项进入“全部 N 种”弹层；弹层包含完整列表和仅查找 Badge 名称的输入框。
- 主栏始终显示“已选 N 种”状态，即使某个选择来自弹层，也不会看起来像没有筛选。弹层保留勾选状态，点击外部或 Esc 关闭，不清空条件；窄屏同样限制工具栏占用。
- 完全没有 Badge 时不显示这一行，维持现有界面。只有一种 Badge 时仍显示，方便突出带标记的卡片。

不建议把所有 Badge 塞进搜索输入框内部：关键词和结构化选择需要各自可见、各自清除。

## 4. 组合逻辑

点击 Badge 是按**确实存在的 Badge 元素**匹配，不是把文字填进搜索框。仅在正文中写了 `logits-based`、但没有相应 Badge 的卡片，不会被 Badge 条件选中。

首版支持多选，默认“任一”。选择两个以上时显示明确的“任一 / 全部”选项，便于区分并列分类和交叉属性：

| 条件 | 含义 |
| --- | --- |
| 仅输入关键词 | 保持现有文字搜索行为，Badge 的显示文字仍属于可搜索正文 |
| 仅选 logits-based | 突出确实带该绿色 Badge 的卡片 |
| logits-based + sampling-based，任一 | 包含这两种 Badge 中至少一种的卡片 |
| sampling-based + distortion-free，全部 | 同时含这两种 Badge 的卡片 |
| 关键词 + Badge 条件 | 必须同时满足关键词和 Badge 条件 |
| 没有关键词且没有已选 Badge | 无筛选状态，不把全图画成“全部命中” |

内部关系为：`结果 = 关键词条件 AND Badge 条件`。没有填写的一类条件不作限制。“全部”要求在同一张卡片中同时具有所有选定 Badge，而非整张 Canvas 中出现过即可。

模式在当前页面内保留，刷新恢复“任一”。清空全部 Badge 后重置为“任一”，避免下次选择继承不明显的旧条件。

## 5. 结果与现有交互

### 突出显示和计数

- 所有最终结果卡片描边，其余卡片按照现有开关淡化；连线和标签按最终结果集合计算淡化。保留全部卡片的位置、尺寸和层叠顺序，不隐藏或重排。
- Badge 筛选本身不把普通正文中的同名词当成文字命中，也不覆盖卡片内原有 Badge 的颜色。
- 有关键词时，画布中只高亮最终结果卡片内的文字命中；状态显示“符合条件 3 张 · 关键词 7 处”。其中“7 处”仅统计这 3 张卡片。
- 仅有 Badge 条件时显示“符合条件 5 张”，不把 Badge 数量冒充关键词出现次数。
- 零结果时清除旧描边、正常显示全图，并明确提示“没有同时符合关键词和 Badge 条件的卡片”；不让全图变得难以阅读。
- 主栏的全局覆盖数不与结果数混用。不同 Badge 可覆盖同一张卡片，各项覆盖数不能直接相加作为结果数。

### 清除、导航与阅读

| 操作 | 行为 |
| --- | --- |
| 输入关键词或切换 Badge / 匹配模式 | 更新结果，不自动缩放、平移、展开折叠内容或切换阅读卡片 |
| 搜索框旁“清除”或搜索框内 Esc | 仅清除关键词，保留 Badge 条件 |
| “重置 Badge” | 清空 Badge 选择、恢复“任一”，保留关键词 |
| Badge 弹层内 Esc | 只关闭弹层，不传播成清空搜索或关闭阅读面板 |
| “上一张 / 下一张”、搜索框内 Enter / Shift+Enter | 只在最终结果中导航，沿用现有几何顺序；修改条件后重置当前结果序号 |
| “查看全部结果” | 适应最终结果；“适应全图”仍展示整张 Canvas |
| 结果导航且阅读面板已打开 | 同步切换面板；面板关闭时不自动打开 |
| 阅读中的卡片被新条件排除 | 保持当前正文和滚动位置，可附一行“不在当前筛选结果中”；保留“阅读中”来源标记，不将它额外计为结果 |

有关键词时优先定位第一处文字命中；仅选 Badge 时定位首个满足选择的 Badge。若该 Badge 位于折叠内容中，仅在用户主动导航时展开所需段落并滚动到它。阅读面板对自己的副本执行相同定位，不把副本加入计数。

阅读面板中的关键词高亮仍服务于当前阅读正文；即使当前卡片被 Badge 条件排除，也不强制清空其关键词高亮。面板不会因为输入或筛选而自动换到别的卡片。

## 6. Badge 的识别与身份

### 收集范围

从原始 `.sce-scene` 中每张文本卡片的正文扫描 `span.badge`，构建 Badge → 卡片 ID 集合及卡片 → Badge 集合。

- 包括需要滚动才能看到的 Badge，也包括原生 `details` 中暂时折叠的 Badge：这是卡片的完整标记信息，不随阅读时展开或收起改变目录数量。
- 排除工具栏预览、阅读面板副本、空文字、代码示例、占位内容、显式隐藏或装饰性内容。代码块里的 `&lt;span class="badge"&gt;` 是普通代码，不是 Badge。
- 原始文字搜索仍遵守现有可搜索正文规则，不因 Badge 目录包含折叠项而扩展为搜索隐藏文字。
- 不收集 SimpleBadge 中已保存但本 Canvas 未使用的预设，也不扫描其他笔记。

### 去重键

推荐使用序列化的 `[文字, 颜色种类, 颜色值]`，不把拼接字符串当作不可能冲突的 ID：

- 文字按 DOM 已解码文本去除首尾空白，保留大小写和内部空白，以兼容 SimpleBadge 的相同 Badge 判定。
- 主题色使用 `theme + green` 这样的稳定语义；主题实际渲染 RGB 改变不会把它变成另一种 Badge。
- 自定义色使用 `custom + #aabbcc`；`#ABC` 与 `#aabbcc` 合并。同名而不同颜色分别列出；相同实际 RGB 的主题色与自定义色也不混同。
- 对手写、缺少受支持颜色标记的 `span.badge`，可按冻结后的实际颜色作兼容归类；使用单独的 `rendered` 类型，不能据此猜测它对应哪个 SimpleBadge 预设。
- 相同 Badge 的展示字号、字体、边框等外观差异不作为身份。主栏选择一个稳定的外观代表并统一尺寸。

同名异色项在可访问名称和提示中补充“绿色”“紫色”或 HEX 色值；不只依靠颜色区分。

## 7. 两个插件如何配合

**首版不要求修改 OB-SimpleBadge。** 它已经把文字和颜色信息写进正文，足以建立文档内的分类目录。预设 ID 不在正文里，也不适合作为导出后文档的身份依据。

SimpleCanvasExporter 需要在样式冻结之前读取 Badge 颜色，向自己生成的 span 添加经过校验的导出元数据，例如 `data-sce-badge-color-kind` 和 `data-sce-badge-color`。这样主题色保留名称，自定义色保留规范化 HEX；视觉仍使用现有冻结样式。这些属性仅由导出器定向生成，不放开任意原始 HTML 属性透传。

浏览器基于这些元数据及原始正文建立索引，不再访问 SimpleBadge 的配置或代码。现有 SimpleBadge 已插入的 span 即可兼容；新导出器重新导出后获得功能，旧 HTML 不会自行升级。

当前无需建立两个插件之间的实时接口，也不需要向 SimpleBadge 添加“分组”“层级”或同步预设功能。若未来要对标签重命名、别名和跨文档统一身份，再单独设计共享格式。

## 8. 实现与验收边界

- 导出阶段：在 `src/styles.ts` 的冻结流程或 `src/render.ts` 中定向写入 Badge 颜色信息；不改原笔记和卡片几何。
- 查看阶段：在 `src/viewer.ts` 中分开保存关键词、Badge 选择、匹配模式和最终结果；不能继续把“关键词为空”直接等同于清空所有结果。
- 导航结果同时支持文字 Range 和 Badge 元素定位，避免仅 Badge 筛选时继续访问不存在的关键词偏移。
- `src/viewer-html.ts`、`src/styles.ts`、`src/i18n.ts` 增加筛选行、目录弹层、状态和中英文可访问文案。工具栏高度变化沿用现有视口及阅读面板布局逻辑。
- 检查相同 Badge 多次出现不重复计卡片、同名异色、等价 HEX、实体文字、Unicode、代码示例、隐藏项、折叠项、零 Badge、大量种类、长名称、阅读副本排除。
- 检查关键词与任一/全部条件交叉后的卡片数、关键词次数、高亮、连线、导航和面板内容；确认点击筛选不改变画布中心或源正文滚动。
- 浅色/深色、320px 窄屏、键盘/触屏和缺少文字高亮 API 时均可用。打印隐藏筛选控件和装饰；禁用 JavaScript 时仍保留原始静态内容。

首版不包含 Badge 编辑、批量插入、同步回 SimpleBadge、按颜色单独筛选、排除条件、嵌套条件表达式或保存筛选方案。
