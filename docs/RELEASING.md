# Releasing Simple Canvas Exporter

## Prepare the source

Use Node.js 22.16 or later and pnpm. From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm test:search
pnpm release
```

This runs lint, unit tests, the production build, and metadata checks, then prepares `release/simple-canvas-exporter/`. Runtime code is bundled into `main.js`; the development QA entry is not included. Refer to [TESTING.md](TESTING.md) for the separate Obsidian and browser test workflow.

Keep `manifest.json`, `package.json`, `versions.json`, and the HTML generator version in `src/export.ts` consistent when increasing the version. Declare a minimum Obsidian version supported by actual testing.

## Upload to GitHub

1. Create a public GitHub repository and upload or push this source tree. Include the lockfile, manifest, styles, source, tests, scripts, documentation, README images, and MIT license.
2. Honor `.gitignore`: dependencies, package caches, generated `main.js`, `qa/`, and `release/` are local outputs. The root manifest and styles **are** source files and must be committed.
3. Confirm that the default branch builds with `pnpm install --frozen-lockfile` followed by `pnpm check`.
4. Create a public, non-draft GitHub Release. Its tag must exactly match `manifest.json`'s version: **`0.3.0`**, without a `v` prefix. Use the corresponding entry in [CHANGELOG.md](../CHANGELOG.md) for release notes.
5. Attach **`main.js`**, **`manifest.json`**, and **`styles.css`** from `release/simple-canvas-exporter/` as three individual release assets. A ZIP containing the plugin folder is optional and does not replace these individual files.

The source ZIP automatically generated by GitHub is not the installable plugin package.

## Submit to the community directory

Follow the [official submission instructions](https://docs.obsidian.md/plugins/releasing/submit-plugin). The current process uses the [Obsidian Community portal](https://community.obsidian.md): sign in, connect your GitHub account, and add the public repository. The portal checks the default branch, release assets, build, and source before community review.

Review the [submission requirements](https://docs.obsidian.md/community-directory/submission-requirements-for-plugins) and [developer policies](https://docs.obsidian.md/community-directory/developer-policies). The README documents desktop support, unsupported content, local file handling, export-time network behavior, and the internal Canvas path adapter.

Passing local checks means the project is ready to upload and submit; acceptance and plugin ID availability are decided by Obsidian's review process. No repository, release, or community entry is created by the local build commands.
