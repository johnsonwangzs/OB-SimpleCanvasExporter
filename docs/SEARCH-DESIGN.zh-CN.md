# 导出 HTML 的搜索与突出显示方案

日期：2026-09-17。状态：已在 v0.2.0 实现并完成浏览器回归。以下保留方案依据与首版交互约定；实际验证结果见 [TESTING.md](TESTING.md)。

## 1. 目标与推荐方案

在浏览器打开导出的 HTML 后，输入关键词，让所有正文包含该关键词的文本卡片同时突出显示，便于观察结果在 Canvas 上的分布，再逐张阅读。

推荐默认组合：**命中卡片外圈描边 + 正文关键词底色高亮 + 非命中卡片适度变淡**。提供一个“淡化其他卡片”开关，默认开启。关闭后保留描边和正文高亮。

搜索作为导出页的本地阅读功能，不写回 Canvas，不需要 Obsidian，不请求网络。新版本导出的文件自带该功能；已经生成的旧 HTML 需要重新导出才能获得它。

## 2. 已核实的实现基础

- `src/viewer.ts` 当前只提供缩放、平移、滚动和视口调整，没有自建搜索功能。因此本方案需要增加导出页搜索框；浏览器原生查找继续独立使用，首版不接管 Ctrl/Cmd+F。
- `src/export.ts` 为卡片保留了 `data-node-id`、`data-node-type` 和固定几何尺寸；每条 SVG 连线都有 ID、起点和终点 ID。
- `src/render.ts` 输出完整静态正文，长卡片通过 `.sce-card-scroll` 裁切与滚动。搜索可以覆盖首屏之外的内容，无需重新读取源笔记。
- `src/styles.ts` 保留主题及 Badge 样式，卡片外壳有 `overflow:hidden`。搜索装饰应独立于正文与原有边框，避免增加卡片尺寸或改变换行。
- 连线标签目前没有对应连线 ID；实现联动淡化时需要补充关联属性。

## 3. 视觉层级

| 对象或状态 | 建议表现 |
| --- | --- |
| 未搜索 | 完全保持当前导出效果 |
| 所有命中卡片 | 保留原背景和颜色，增加约 2 屏幕像素的主题强调色外圈 |
| 正文中的所有命中词 | 使用能与明暗主题配合的底色和前景色，不改字号、粗细、字距或行高 |
| 当前定位卡片 | 外圈约 3 屏幕像素，增加“当前”标记；区别于其他同样命中的卡片 |
| 非命中卡片 | 默认以约 40% 的相对不透明度显示；位置和交互仍保留 |
| 正在阅读的非命中卡片 | 鼠标停留或键盘焦点进入时暂时恢复可读亮度，不增加命中描边、不计入结果 |
| 无匹配结果 | 显示“未找到匹配的文本卡片”，保持全图正常亮度，清除旧的高亮 |

这里的“变淡”是降低视觉权重：深色主题下接近背景，浅色主题下同样向背景淡化。不要固定盖一层黑色，也不要全局模糊。具体不透明度先用 40% 做视觉验收，必要时在 35%～50% 范围内调整。

卡片颜色和 Badge 已有语义，搜索不将整张卡片重新染色。无需闪烁或循环发光。非命中内容不隐藏、不重排；重叠卡片的层叠顺序也不因搜索改变。

外圈以视觉上的屏幕宽度为目标，不能在“适应全图”时随场景缩小到几乎看不见。建议使用独立、不可交互的装饰层，按缩放比例补偿线宽。极小缩放下可隐藏“当前”文字标记，保留外圈。

### 连线

仅当搜索有结果且“淡化其他卡片”开启时：

| 两端状态 | 连线及标签的建议相对不透明度 |
| --- | --- |
| 两端都命中 | 100% |
| 仅一端命中 | 60% |
| 两端都未命中 | 20% |

上述比例叠加在原始外观上，不覆盖主题的线条颜色、箭头、线宽和路径。关闭淡化、清空查询或零结果时全部恢复。首版不沿连线递归把相邻卡片算成命中。

## 4. 工具栏与阅读流程

宽屏保留标题和原有缩放操作，增加搜索区：

```text
[搜索文本卡片…       ×]  命中 3 张 · 7 处
[上一张] [下一张] [查看全部结果]  [✓ 淡化其他卡片]
```

结果导航以卡片为单位；“7 处”只说明关键词总出现次数。激活导航后补充“当前 2/3 张”，避免把卡片数与词频混在一个计数器中。导航顺序固定按卡片上边缘 y、左边缘 x、源数据顺序排列，与当前缩放和平移无关。

1. 输入 `xxx`，所有命中卡片同时描边，正文中的命中词同时高亮。
2. 输入期间只改变搜索状态，保持画布位置和所有卡片的正文滚动位置。首次输入不自动跳到某个结果。
3. 点击“下一张”或在搜索框中按 Enter，定位第一张命中卡片；继续操作循环到下一张。Shift+Enter / “上一张”反向循环。
4. 定位时先把目标卡片移到视口中心；若当前视图过远则提高至适合阅读的比例，通常不超过 100%。目标较大时允许正文滚动，不为塞入整个外框而将文字缩得过小。已经足够清晰且在视口中的目标不额外缩放。
5. 只在用户导航时，将目标卡片的首个命中词滚入其内部可视区域；必要时同步处理代码块或表格内的横向滚动。其他卡片不自动滚动。首版不提供逐词跳转。
6. “查看全部结果”将所有命中卡片的外框纳入视口，保留当前搜索和原始坐标；原有“适应全图”仍展示整张 Canvas。如果结果分布很远，允许缩小，由用户再逐张定位阅读。
7. 点击清除按钮或在搜索框内按 Escape，清除查询、结果计数和突出效果。停留在当前阅读位置，不突然回到初始视角，也不恢复导航前的正文滚动位置。

搜索框保持键盘焦点，连续 Enter 可以继续导航；输入法正在组词时不搜索半成品，也不把确认汉字的 Enter 当作导航。Escape 只在搜索控件内处理，避免影响普通正文操作。

工具栏在窄屏可换成两行，搜索输入框保留可用宽度。视口上边缘应随实际工具栏高度变化，不能继续写死为当前的 58px。

## 5. 匹配规则

| 项目 | 首版规则 |
| --- | --- |
| 范围 | 仅文本卡片中实际导出的可读正文，包括标题、段落、列表、表格、代码、Badge 和双链的显示文字 |
| 长卡片 | 搜索完整正文，包括目前在滚动区域之外的文字 |
| 匹配方式 | 字面子串，英文默认不区分大小写；中文直接匹配 |
| 多字与短语 | 整个输入作为一个短语，不自动拆成 AND/OR 关键词 |
| 空白 | 去除查询首尾空白；连续显示空白按一个空格匹配；空查询退出搜索 |
| 特殊字符 | `.`、`*`、`[`、`+` 等均按普通文字处理，不解释为正则 |
| 跨标签 | 连续文字被粗体、链接等行内标签分开，仍可命中；块级边界加入分隔，避免两个独立段落直接拼出不存在的词 |
| 计数 | 一张卡片无论出现多少次，只计一张；总处数按从左到右的非重叠匹配统计 |
| 不搜索的内容 | HTML 标签和属性、链接隐藏目标、节点 ID、图片像素和替代属性、导出器生成的资源占位说明、工具栏文字 |
| 其他节点 | 文件、网页、分组当前均未完整支持，首版不把它们的占位文字纳入搜索；连线标签也不纳入搜索 |

普通外部链接的显示文字可以匹配，但目标 URL 只有在正文中实际展示时才参与。双链若显示别名，只搜索别名，不暗中搜索未显示的笔记名。

首版不提供正则、模糊匹配、拼音、简繁转换、全半角等价、布尔查询或多词分色。后续有明确需求再扩展，避免“输入一句话到底怎么匹配”的歧义。

## 6. 实现建议

### 搜索索引与状态

导出页首次打开时，为每张文本卡片建立一次轻量索引：可读文本、原始 DOM 文本节点及字符位置映射、卡片 ID 和几何信息。索引只来自导出正文，不在 HTML 中再复制整份原始 Markdown。

用 DOM 遍历构建文本流，排除隐藏元素与导出器占位节点，记录块级分隔和空白折叠的位置映射。索引规范化后的每段位置都应能还原到 DOM Range；不要假定大小写转换后字符串长度永远不变。搜索与高亮共用同一套结果，防止计数和着色不一致。

状态最少包括：查询、命中卡片集合、各卡片命中范围、当前卡片索引、是否淡化。输入约 120ms 防抖；在 compositionend 后计算中文输入结果。清空立即生效。大文档的索引与匹配可分批执行，用查询版本号丢弃过期结果，避免新查询被旧结果覆盖。

### 正文高亮

优先使用 DOM Range 配合 CSS Custom Highlight API。它可以对指定文字范围着色而不改变正文 DOM 结构，适合本项目已有的冻结样式、链接和 Badge。[W3C 规范：Introduction](https://www.w3.org/TR/css-highlight-api-1/#intro)

运行时检测能力，不依赖浏览器名称或假设版本。缺少该能力时，首版降级保留卡片描边、淡化、计数和卡片定位，工具栏提示“当前浏览器仅支持卡片高亮”；不为降级反复改写正文 `innerHTML`。跨行、跨行内标签及彩色 Badge 需要实际验证高亮前景与背景的对比度。

已在本机 Edge 验证词级高亮，并通过禁用 Highlight 构造器模拟缺少该能力的浏览器，验证计数和定位降级。其他浏览器版本仍需实际验证。

### 与现有代码衔接

| 文件 | 预期改动 |
| --- | --- |
| `src/export.ts` | 增加搜索工具栏和文案数据；为连线标签补充关联 ID；输出搜索装饰层 |
| `src/viewer.ts` | 初始化索引和搜索状态；复用现有 scale/x/y 与 paint；增加定位卡片、适应结果范围、工具栏尺寸联动 |
| `src/styles.ts` | 增加高亮、外圈、淡化及窄屏样式；打印时恢复卡片和连线原始外观并隐藏搜索装饰 |
| `src/i18n.ts` | 搜索占位、计数、导航、清除、淡化、无结果和能力降级文案 |
| `src/render.ts` / `src/assets.ts` | 对导出器生成的占位内容统一标记为不参与搜索，确保清理后标记仍保留 |
| `scripts/browser-test.mjs` / `tests/` | 新增搜索验收样例和浏览器交互检查 |

`startViewer` 当前经 `toString()` 内嵌到导出 HTML，新增运行逻辑必须仍然自包含；不能随意引用外部模块变量或导入函数。若拆模块，先调整浏览器脚本的打包与内嵌方式。

当前 `[data-action]` 点击处理将未知操作当作缩小处理。新增搜索按钮必须用独立选择器或显式分发，防止“下一张”误触发缩放。

避免用 `scrollIntoView()` 一次性移动所有祖先容器。应分别控制画布的变换和目标卡片内部的滚动，使连接线与卡片持续对齐。搜索外圈和淡化样式的层级需高于主题快照规则，但清除后能够完整恢复原样。

查询只保存在当前页面内存，不写入源文件、URL 或本地持久存储；刷新回到未搜索状态。正文、链接和拖选仍保留原有交互。打印默认输出正常全图，不携带临时搜索突出效果。

## 7. 首版验收

- 同时命中多张卡片时全部突出；同一卡片多处匹配，卡片数和词频正确。
- 搜索长卡片底部文字仍能匹配；点击下一张后目标词在卡片内部可见。
- 覆盖中文输入法、大小写、短语、特殊符号、跨行内标签、重复搜索、空白与零结果。
- Badge、双链别名、代码和表格参与搜索；隐藏目标与导出占位不出现假结果。
- 输入不引起平移、缩放和正文滚动；导航与“查看全部结果”只在用户操作时改变视图。
- 在浅色、深色、彩色卡片及 Prism 导出样例中检查对比度；较小缩放下仍可辨认命中外圈。
- 淡化开关对卡片、连线和连线标签同步生效；清空和零结果后原始外观完整恢复。
- 高亮前后卡片坐标、尺寸、正文滚动高度和连线路径不变；文字选择、复制、链接和滚动正常。
- 工具栏换行后不遮挡画布；键盘导航和状态播报可用；打印不保留搜索淡化。
- 用本地 `file://` 打开导出文件，搜索全过程无远程请求；无 Highlight API 时降级可用；禁用脚本后原有静态阅读仍可用。
- 使用当前 25 卡片样例与合成的 500 卡片 / 约 100 万字符样例检查响应。以输入结束至稳定结果约 200ms 内为初始目标，记录设备与实际值；如果超出，再对索引、绘制和分批任务优化，不能用截断正文降低正确性。

## 8. 实施范围建议

一次首版交付覆盖：独立搜索框、卡片与词级高亮、可关闭的淡化、两类计数、逐卡片导航、查看全部结果、清除、明暗主题及离线验证。

暂不加入侧边结果列表、只显示命中卡片、多关键词分色和查询语法。先验证“看分布 → 定位卡片 → 阅读上下文”这条完整流程；之后再依据实际使用决定是否需要按词跳转或结果列表。
